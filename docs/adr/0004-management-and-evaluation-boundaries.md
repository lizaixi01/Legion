# 管理核心与领域验收、评测编排分离

2026-10-01，已实施。

HWE 的公开指标曾写死在研究循环中，主会话直接包含 HWE 工具与提示，HWE 宿主执行还依赖 ProgramBench 的通用路径和模型传输。这样更换任务环境会牵动管理代码，也使产品职责与对照实验混淆。用户明确要求先解耦，再提交并推送代码。

提取候选循环和主会话核心，通过宿主安装的质量策略、执行/验证接口及领域能力装配 HWE。指标有效性、比较方向、工具状态解释和环境兼容性由任务环境决定；预算、派工、状态、候选来源与交付门控留在管理层。A/B 入口放入 benchmark harness，产品核心不能反向依赖它。通用路径与模型代理归执行基础设施。

保留原 HWE 接口、CLI、version 1 记录与全部额度语义。新增策略身份旁文件，在恢复前拒绝目标比较策略变化；旧 HWE 记录由兼容入口恢复。FAIL 与基础设施异常不得合并丢失，矛盾 PASS 不能进入排名。readiness、指纹及验证覆盖继续归领域可信边界，冻结证据不迁移。

本轮不合并桌面与研究调度器，不创建独立服务或插件安装系统，不更改实验模型、预算、评分或实际 RTL。离线行为和传递依赖回归验证边界；是否提高管理收益仍需单独实验。实现位置和限制见 [架构说明](../architecture-boundaries.md)。
