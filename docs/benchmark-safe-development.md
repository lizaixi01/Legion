## 开发位置与允许的工作

从同一提交建立单独开发 worktree，使用独立 `codex/` 分支。文档 worktree 为 `C:/Users/HUAWEI/.codex/worktrees/experiment-docs/Proactive Agent`，文档提交位于 `codex/update-experiment-docs`；后续 benchmark 故障修复复用同一工作树，在 `codex/benchmark-reliability` 开发。这是本机位置，不是跨机器安装要求。原检出和实验副本保持原版本。

文档、接口设计和源码编辑可以在开发 worktree 进行。需要测试或构建时，先为该 worktree 准备独立依赖、输出与临时数据，确认测试不调用真实模型、HWE 工具链或全局配置；使用小范围离线测试。当前文档更新只做内容、链接和归档数值核对，不安装依赖、不运行模型或硬件验证。

依赖安装和任何可写输出只能放在开发目录；小范围检查可以只读调用已固定版本的现有类型检查器和测试启动器，不升级或改写共享依赖。2026-10-02 的报告工具使用该方式做轻量离线检查，没有模型、WSL/Docker、仿真或综合调用。

## 共享资源的保护

- 保持批次协议、配置、冻结副本、readiness、baseline、证据和实验输出只读；不对已启动实验注入开发代码。
- 不在原项目运行依赖安装/升级、runtime:install、构建覆盖、HWE 输入更新或工具链升级。开发 worktree 不建立指向实验可写数据的 junction。
- 不修改共享 Codex / Command Code 的模型、推理强度、登录或全局配置；额外真实调用会争抢额度、并发与网络，属于实验外负载，应另行记录和安排。
- 不运行 Docker 全局清理、替换同名镜像、重启 WSL/Docker、停止不属于本开发工作的进程，或同时启动重型仿真/综合/容器 benchmark。开发自有资源使用独立 owner、名称、目录和端口。
- 不在实验所用检出切换/合并分支，不改共享 Git 配置，不做 prune/gc 等仓库维护。worktree 共享对象库和 refs，分支名称、Git 维护也需要避免冲突。

worktree 能隔离源码编辑；它不承诺同一台机器上的性能测量完全不受开发负载影响。需要可比墙钟/资源结果时，以实验优先，限制开发测试负载并记录同时运行的工作。

## 迁移 Worker 候选时的验收对象

后续可为每个 Worker 创建独立分支和 worktree，提交候选后记录 commit 与根 tree。验证器在独立检出中检查该版本，证据同时绑定原需求、外部输入、验证器实现、工具链与实际命令。提交只提供版本身份，不认证功能正确；未跟踪产物、LFS/submodule 内容及其他外部输入仍需单独获取和绑定。Git checkout 的换行/过滤配置也应固定，或对验收的实际文件字节继续核对。

当前哈希快照证据仍有效；无需为了迁移而改写旧运行。先在开发分支实现和离线验证新适配器，保留快照兼容与恢复语义，之后在新冻结批次比较行为。合并 Worker 产物后的根 tree 也应重新验收，不能直接继承各分支的 PASS。

公开重放需要可获取的候选提交/归档、输入、环境、验证器和明确命令；“有 commit SHA”与“第三方能重跑”是不同条件。当前公开资料的缺口见[实验摘要](experiment-summary.md#实现成熟度与复现边界)。
