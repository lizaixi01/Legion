## 实际发生的管理决策

1. Manager（GPT-6 Sol/high）读取公开 baseline，提出共享乘法器和共享除余网络两个假设，各分配 600 秒；两个 GPT-6 Sol/medium Worker 在独立容器并行执行。
2. Worker 导出源码和报告后，新的外部容器逐个验证。程序保留除法分支，拒绝把已通过检查但性能退步的乘法分支作为最佳。
3. Manager 读取第一轮证据，明确淘汰旧乘法分支，从已验证除法快照派生两条新路线：操作码控制的 33 位符号扩展乘法，以及按真实源操作数使用情况减少 load-use 停顿。
4. 第二轮两个最终快照分别重验。一个性能退步，一个契约检查失败；程序最终保留第一轮最佳，在调用上限处停止。

第二轮决策由模型自行产生，没有人工代写假设、修改候选或回灌补充检查。原始 `memory.json`、决策、源码 SHA、Worker 会话、报告与外部日志完整保留。

## 验证范围与负例

- baseline 在本机两个独立容器重复得到相同指标；语法负例和 XOR 改 OR 的可编译错误均被拒绝；实际取消检查后清理了对应容器。
- formal 的上游合计 105 包括 53 PASS 和 52 PREUNSAT（未使用的第二退休通道），不能描述成 105 项非空证明。另有 ALTOPS 对真实乘除法覆盖不足的限制。
- CoreMark CRC 与公开 ISS 程序不是穷尽验证；Fmax 是 FPGA 布局布线时序估计，没有实物板卡测试。
- 第一轮两个候选另通过了独立的上游 ALU 单元测试，记录在各自 `supplementary-alu/`。这些补充结果没有进入 Manager 上下文，也没有改变本轮冻结选择规则。
- 当前公共基准工具可运行，但模型容器未打包可选 cocotb 单元测试目录，不能声称 `make test` 可直接运行。移植和工具版本见 [环境验证](hwe-readiness.md)。
