# 代码工程三臂对照协议草案

日期：2026-10-02。状态：准备阶段，未冻结，未运行三臂。代码工程任务先小批试跑，再冻结 20–30 题。

## 问题与比较单位

研究问题是独立验收能否在工程交付中减少失败，以及收益所需的计算、时间和人工成本。A→B 比较委派组合，B→C 比较外部验收和返工组合；C 包含确定性检查及新会话 Challenger，不能将收益单独归因于其中一个部件。

一题、一个臂、一次完整策略运行是一个样本。运行内的 Worker、候选、检查和返工都消耗该样本的预算，不能把多个 Worker 的最好结果记作多个独立 pass@1 样本。必须在终局评分前冻结最终提交的选择规则；禁止看分数后换候选。

| 臂 | 执行策略 | 执行时外部验收反馈 | 终局评分 |
| --- | --- | --- | --- |
| A：single | 单 Agent、一个解题会话，禁止委派 | 无独立 Challenger/宿主验收门；可自行运行公开测试 | 相同冻结终局评测器 |
| B：multi | Manager + 多 Worker，集成结果，接受自评为主张 | 无独立 Challenger/宿主验收门；可自行运行相同公开测试 | 相同冻结终局评测器 |
| C：multi_verified | 与 B 相同的规划、委派、集成接口，加独立验收与有限返工 | 冻结契约、宿主安装的公开功能检查、新会话 Challenger、证据有效性检查 | 相同冻结终局评测器 |

三个臂都能编译、测试、自查并自然修复。只移除 B 的外部验收门，不能人为禁止其正常工程行为。C 的在线 verifier 必须仅依据公开需求和输入建立；最终评测器由宿主持有，评分及隐藏夹具只在解题阶段全部结束后使用，三个臂都不得读到。

## 任务集与开发隔离

先使用[开发试跑清单](engineering-pilot-tasks.md)检验接线、计量和故障分类。这三项是 Legion 自身真实工程缺口，但已经参与设计讨论，不能作为未调优长程任务的效果证据。缺少可执行评测器的提案不得进入正式运行。

正式集使用 20–30 个独立工程需求，覆盖跨模块功能、缺陷修复、兼容迁移和集成，不以多个相似数字/JSON 题凑数。优先使用允许再分发的真实仓库与可核验 issue；对每题记录需求出处、仓库许可证、固定 baseline commit、公开输入、公开测试和终局评测器哈希。任务集在运行任何正式臂之前一次性选定，不按 C 的表现筛选题目。

难度与“长程”依据独立校准的工程工作量、需协调的模块/依赖和可观察的阶段交接预先定义。实际运行过短、未解出或超时的题仍保留；不能靠强制睡眠/耗尽预算制造长程任务。开发题、调参题及重复需求与正式集分开发布。

终局评测器逐项对应原需求，至少包括跨模块行为和关键边界、既有行为回归，并拒绝空测试、全 skip、篡改权威测试及错误候选身份。用已知正确实现与独立构造的错误实现验证判别力。测试通过仍只证明覆盖范围；缺少验证器的题不能算成功。机器检查难以覆盖的要求须提前标为未覆盖，不能在看结果后临时改成模型评分。

## 公平性与预算

固定后端、模型、推理强度、CLI 版本/实际二进制、原始需求、工具链、输入和 CPU/RAM 上限。A 禁止原生子 Agent，B/C 禁止再套未计量的 Agent team。每个 task-arm 独立会话、检出和可写目录；不共享候选、计划、日志或跨臂记忆。worktree 提供源码隔离，独立容器/权限边界按实际环境另行记录。

主要分析比较相同总资源上限下的完整策略。Manager、Worker、Challenger 均计入模型调用与 token 记录；C 的在线验证占用其时间/计算配额。另行预注册允许 C 更多资源的产品配置，可比较质量/成本曲线；不能将额外资源优势称为纯管理收益。

试跑配置建议每个臂 2 小时、最多 16 次宿主模型调用、多 Worker 并发 2，返工仍在原配额内；这些值尚未冻结。模型调用是执行器级调用，不等于提供商内部请求数。必须在执行器验证真实硬门、用量观测、停止和清理后再确定正式预算。token/货币上限、任务环境、候选选择和重试规则均需在首个真实试跑前补齐，本草案不授权现在启动九次长调用。

逐题随机并平衡执行顺序，保存随机种子和实际排期。避免与其他真实模型运行或重型测试争用资源，记录排队、额外负载与服务故障；工作树隔离不等于性能隔离。

## 失败、重试与 pass@1

预注册每题每臂的 primary run，第一轮完整策略终止后保留原始结果。策略自己的预算耗尽、明确候选失败与正常期限终止是策略结果；认证/网络/启动故障、验证器崩溃等单独记录。没有可评分候选时，不能编造功能性 fail；验证器 error 也不等于候选错误。

主报告同时展示：

- **端到端 pass@1**：第一次完整策略运行的成功数 / 全部预注册 task-arm 数。基础设施故障和评估错误属于端到端非成功，但在归因中单列，绝不标为解题失败。全部 primary run 终止前不发布最终比例。
- **已评分解题通过率**：pass / (pass + 明确 fail)，旁边必须展示基础设施/评估错误、unverified 和未完成数量；它不能替代全样本结果。
- **同题配对分布**：两臂都通过、都失败、仅一臂通过及被基础设施/评估问题阻断的题。正式分析依据配对任务而非假定各 Worker 独立；不将 20–30 个不同任务说成同题重复或足以支持所有产品场景。
- **失败归因**：需求误解、实现、集成、预算/期限、unknown；基础设施、评估错误与 unverified 独立列出。归因必须附原始证据，模型自评不能直接成为事实。

预注册的基础设施恢复可以另跑，但不能用成功重跑覆盖 primary，也不能换掉失败题。恢复原因、全部用量和结果独立发布。需要分析“环境可用时的效果”时另给带覆盖率的恢复后结果，不偷换第一次运行的定义。正式任务失败后的解题重试是新的 run，不是免费的基础设施恢复。

## 成本、时间与人工

分别报告 input、cached input、uncached input、output；总 token = input + output，cached 是 input 的子集。缺失观测写 null。所有策略角色、失败尝试、独立验收和恢复都纳入成本；共用预检/环境准备另列批次开销，不能悄悄丢弃。

wallMs 记录该 primary run 从启动到终局评测结束的实际时间，包括排队和在线验收；另保留各阶段时间，不能将并发 Worker 时长相加后当墙钟。恢复尝试单独计时，费用仅记录实际可观测金额；订阅账号拿不到金额时保留 null，不把 API 等价估算当账单。CPU/GPU/验证器时间及工件存储开销在原始阶段日志中保留。

人工时间包括澄清、审批、环境修复、监督、验收和返工。比较 AI 分数不能替代人效比较；没有人工基线及完整时间记录就不宣称“10 倍效率”。

## 离线报告入口（已实现）

```sh
npm run --silent experiment:report -- docs/experiment-data/engineering-pilot-plan.json
npm run test:experiment-report
```

首条命令只读输入并将 JSON 报告输出到标准输出，不调用模型、修改候选或启动工具链。当前示例是三题、九个 planned primary run 的空草案；pending 为 9，最终 pass@1 和未知成本为 null。它不是实验结果。

输入类型见 [ExperimentStudy](../src/experiment-report.ts)。每题需要 baseline commit、公开输入和 final evaluator 的 SHA256；frozen 还需要协议与任务集 SHA256。每条 primary 包含 state、termination、明确 grade、原始证据路径、成本和 recoveryAttempts；budget 退出与最终候选 pass 可同时存在，不能将其写成策略主动完成。报告器拒绝重复 primary、未知任务、不可能的缓存计数和模糊成功字段，但它**不认证证据、不开启实验、不实现预算硬门，也不提供统计显著性结论**。填写了哈希不等于材料可下载或原始 grade 可信。

## 公开与阶段门

1. **准备**：发布协议、题目来源/授权、执行与验收接口；开发试跑题的可执行终局检查和三臂开关还需实现。此阶段只能发布准备状态。
2. **试跑**：所有评测器与隔离预检就绪后冻配置，跑三题三臂，保留所有有效失败和基础设施错误。依据接线故障修复实现，不能将这组调参结果充当正式效果。
3. **正式集**：用新任务冻结 20–30 题，发布任务集标识、排期、预算与停止规则。解题期间暂不发布隐藏终局夹具；全部运行结束后公开可再分发的完整评分材料。
4. **结果**：发布完整分母、逐题结果、配对差异和不确定性、成本/时间/人工、原始失败及覆盖范围，无论正负结果都发布。

每份公开证据包至少可获取候选 commit/tree 或带 SHA256 的归档、公开输入、验证器源码与版本、环境锁定文件或可获取镜像、实际调用命令和原始退出/评分记录。必须用新目录独立复验其命令后，才能称“一条命令重放”。报告命令只重算统计，不能代替候选复验或复跑模型。
