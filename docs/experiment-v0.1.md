## 2. 对照与处理

| 项目 | B0 | B1 |
|---|---|---|
| 起始状态 | 独立干净容器、原始输入 | 独立干净容器、同一份原始输入 |
| Worker | 固定 Codex CLI，gpt-6-sol，high effort | 完全相同 |
| 初始 prompt | 任务说明 + 相同检查工具说明 | 字节一致 |
| 可见工具和知识 | 相同公开检查、任务输入、软件 | 相同 |
| 子代理 | 显式关闭并验证 | 相同 |
| 首次 worker 阶段 | 最多 5 小时 | 最多 5 小时 |
| 正常退出后的检查 | 执行并保存；不再反馈 worker | 执行；明确失败时提供报告 |
| 额外 worker 阶段 | 无 | 恢复原 session ID 一次，最多 2 小时 |
| 修复后检查 | 不适用 | 执行并保存，不再续跑 |
| 最终评分 | 全部 agent 工作结束后一次 | 相同 |

这是自建 Codex 配对基线，不声称复现历史 ALE 官方成绩。使用相同当前 CLI 可避免把旧 fork 的兼容问题误归因为管理效果。若选定 CLI 无法接入 ALE 工具，应解决两组共同的兼容层；不允许只给一组额外工具或补丁。

处理组没有 LLM manager，也不生成领域求解方案。修复 prompt 只包含固定指令、原始公开检查报告及剩余时间，不加入人工或 manager 的航天解题提示。

## 3. 时间、资源和停止

时间值由助手根据用户授权确定：

- 每组首次 worker 最多 5 小时；B1 额外修复最多 2 小时。
- 每次外部公开检查最多 10 分钟；检查自身崩溃或超时记为检查错误，不当作明确产物失败触发修复。
- 每组最终 grader 最多 30 分钟；超时归为评估错误，不写成有效零分。
- 环境就绪后，一对运行总期限 14 小时。下载、构建和首次兼容预检独立计时，不计入 agent 解题时间。worker 结束即推进，不为耗尽预算继续运行。
- 每组容器初始设为 4 vCPU、8 GiB RAM，单并发；在任务运行前验证依赖与资源可用性。若预检证明不足，先统一调整两组配置再冻结，不在单个处理组中途加资源。
- 不设金额或 token 硬上限；记录实际用量。额度不足、登录过期或模型不可用时保存现场并停止，不自动换模型、账号或付费方式。
- worker 超时属于该策略在所设时间下的终止结果，不能因为它失败而事后剔除。正常退出才满足本版修复触发条件。若基础设施无故杀死进程，则另记基础设施失败。
- 运行中的模型、checker、输入、工具和资源配置不得修改。预检失败可以修复后重做；有效任务失败不能被当成预检失败反复筛选。

## 4. 公开检查边界

唯一领域依据是固定版本的 problem_spec.md、task_prompt.md、output_contract.json 及 runtime manifest，不读取隐藏参考或评分器阈值来设计 checker。

首版覆盖：四个要求文件、JSON 结构与必要字段、数组列数和合法实数、有限数、时间有序和同步、公开起止时间、标量与终点一致性、公开质量/控制/轨道几何约束、公开初末边界条件。实施时每条断言必须标注公开规范出处；不能自行收紧容差。

完整动力学局部缺陷、最优性、全时段独立重放和隐藏参考燃料门槛记为 not_checked，不得混入 pass 计数。检查报告区分 pass / fail / not_checked / error。产物缺失、格式非法可以是明确 fail；检查程序错误、输入契约不匹配属于 error。

外部检查必须使用受保护的固定 checker；两组 worker 可调用同一版本但不能修改权威副本。输出扫描是只读操作，不修复、删除或重写候选产物。

## 5. 信息隔离与基准接入

- ALE 保留环境创建、输入 staging、终局评分和日志收集职责。管理策略放在 agent 的执行阶段内部。
- manager/worker 只看任务公开输入、自己的文件和运行日志；不挂载包含隐藏参考、整套 benchmark 源码、另一组日志或本研究笔记的宿主目录。
- 使用干净的实验配置目录，避免个人 AGENTS、skills、MCP、记忆和历史会话影响 worker；仅继承必要登录能力，凭据不写入结果或日志。
- 每组结束后杀净 worker 及其子进程，再开放 reference 进行评分。评分后不恢复该组会话。
- 首轮顺序在运行前记录，单并发完成；一对样本不能消除时段漂移或顺序效应。后续重复实验需要平衡顺序。
- 禁止跨组复用解题产物、会话和管理记忆。共享原始输入及固定 checker 是实验设计的一部分。
- 任务数据与 ALE 代码分别固定 revision/hash，并检查兼容性。公开数据 main 的版本不自动等于所固定代码的版本。

## 6. 最小架构

仅保留一个运行记录、最多两个 attempt、结构化检查报告、预算计时器和固定状态机。无需 Goal/Task 动态图、候选动作生成器、SQLite、通用事件溯源、并行 worker 或主动感知。

```text
ALE 生命周期
  → 薄 Python deployer
    → TypeScript 固定管理流程
      → Codex CLI 首轮
      → Python/NumPy 公开检查
      → 条件满足时 resume 同一会话一次
  → ALE 最终评分与收集
```

建议目录（尚未创建代码）：

```text
src/
  cli.ts               # 配置和运行入口
  run.ts               # B0/B1 状态机、预算和持久化
  codex.ts             # exec/resume、退出和原始日志
integration/ale/
  deployer.py          # ALE 接口及轨迹汇总
checks/
  aerospace.py         # 仅公开规范检查
configs/
  pilot.json           # 两组共用配置及处理差异
tests/                 # 行为测试和少量数值边界 fixture
docs/
```

state.json 原子保存当前阶段与 attempt/session 身份；manager.events.jsonl 追加关键事件和固定决策原因。二者不升级为通用事件重放系统。worker 每次调用使用独立日志目录；不可覆写前次 evidence。

发生管理进程崩溃时，先核对原 worker 是否仍存活；无法确定则停止并标为需恢复的基础设施状态，不盲目启动第二个 worker。自动跨进程崩溃恢复不是首轮研究干预，先确保可审计、可安全停止。

## 7. 计量与结果

复用 ALE run.json、trajectory.json、eval_result.json、events.jsonl 和 origin_log；补充 attempt ID、session ID、外部检查报告、管理阶段时间和输出哈希。保留原始 usage 事件，验证 resume 报告是增量还是累计，缺失值记 null 而非零。

记录：ALE 提交、数据版本、模型实际标识、CLI 版本及哈希、登录方式类别、effort、功能开关、工具与 prompt 哈希、镜像 digest、资源限制、初态标识、每次尝试状态与耗时、input/output/cached tokens、可观测成本、检查结果、退出原因、人工干预和最终产物。

如果使用 ChatGPT 账号登录，无法取得实际货币成本时明确写“不可观测”，不把公开 API 标价当实际账单。可另外报告有来源和日期的 API 等价估算，但不是必需项。不得把总 token 与缓存 token 重复相加。

最终报告并列展示 B0/B1 的官方成绩、检查覆盖与结果、额外耗时/用量以及全部失败。第一对无论结果如何都不报告成功率提升百分比或显著性。

## 8. 验证与实施顺序

1. 兼容预检：确认 CLI 模型访问、登录在隔离环境中的可用性、exec/resume、禁用子代理、两轮用量对账、WSL Docker 和文件/进程权限。先用极小非任务提示验证，不消耗任务样本。
2. 固定输入与检查：核验公开数据版本，编写检查及合成错误 fixture；不使用隐藏参考做测试。
3. 本地状态机：用假 worker 验证 B0 不续跑、B1 仅失败续跑一次、正常通过停止、checker error 不触发修复、超时终止、日志不覆盖和恢复时不重复启动。
4. ALE 接入：先验证环境和数据 staging、评分后禁止 agent 存活、轨迹和 token 汇总完整。隐藏参考由评分流程使用，manager 不读取。
5. 运行一对：冻结配置，执行、保留有效失败，最终输出可审计对比和下一步假设。若访问或环境阻塞，报告具体阻塞，不以可见检查替代 ALE 成绩。

后续扩展另行依据证据决定：增加公开检查覆盖、重复样本、固定续跑对照、LLM 管理决策、未调优任务。首轮不同时实现这些项目。
