# 通用主会话

2026-10-04。普通聊天与显式持续目标都使用 `chat-service → primary-agent → primary-runtime → codex-app-server`。默认主会话具有自身执行与管理职责，读取外部项目的说明、文件与命令，并保留用户约束。

## 默认工具与交付

- `legion_dispatch`：按配置的后端、并发、调用预算和期限派发有界任务，保留契约与版本记录。
- `legion_tasks`：查看容量、任务与完整尝试历史；等待、取消或在预算内继续。Worker 自述不是认证。
- `legion_delivery`：实现前登记不可变要求；集成后固定产物、独立复核、宿主重放与功能检查。后续修复沿用要求并重新验证。

默认装配不安装项目专用工具。宿主可显式使用现有 `PrimaryCapabilityFactory`，提供能力及其清理；模型不能注册能力。`primary-strategy` 仍可供明确的宿主能力使用，默认桌面不注册它。

当前默认功能认证覆盖内置数值聚合；其他文件可以获得独立审查证据，功能覆盖不足保持 `unverified`。每轮最多三次交付检查。快照规则与原文件大小限制保留；已登记交付未验收、必需 Worker 未收尾或证据失效时，主会话不能正常完成。

## 任务记录与资源

失败尝试在修复后仍可读。任务等待不启动工作，批量等待返回紧凑状态，摘要明确区分已观测回报和可信证据。取消传播到进程及共享队列，收尾保留不确定结果；队列和检查系统分别遵守已有容量与预算。

聊天详情只读取通用消息、任务、交付、决策与预算。历史附加字段被安全忽略，旧领域记录保持原字节；历史通过记录不能直接授权新派发或认证当前文件。旧装配会话在用户继续发送时建立新的通用会话并带入历史上下文，不恢复旧工具表；交付要求和持续目标累计预算、期限沿用原记录。

模型与 effort、Manager 与 Worker 的服务档位请求保持独立。界面开关表示请求偏好；实际服务档未观测时仍为未知，不能从延迟推断。

## 原生持续目标入口

持续目标向 `chatSend` 传 `continuous`，复用普通工具链。原生目标先以 paused 登记，启动用户轮次后激活；监听后续目标和轮次事件，Legion 不额外叠加轮次循环。停止或连接结束时暂停仍活动目标，保留原目标、会话和期限。

默认总期限仍为六小时，累计 64 次 Worker/独立复核调用和 3 次宿主检查账本。恢复不重置次数、未知占用或期限；独占租约防止两个连接接管同一目标。默认交付检查仍按自己的每轮三次上限执行，未改变累计账本语义。原生 token 数仅代表主会话，不包含全部独立 Worker 成本。原生 complete 与通用交付 accepted 分开显示。

旧持续目标和工程任务仍有独立恢复入口，见[恢复设计](resumable-engineering.md)。关闭应用后不常驻；真实模型与多日可靠性不在本轮离线验收范围内。
