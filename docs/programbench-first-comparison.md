## 方法与限制

- 相同任务、镜像、Codex 0.157.1、GPT-6 Sol/medium、公开案例及每次 480 秒模型执行上限；每个 Worker 2 CPU / 4 GiB。执行时间包含容器准备、导出、检查等开销，因此可超过 480 秒。
- A 是单次完整会话，可自行测试和修改，关闭子 Agent，不由外层续跑。正常提交即评分，公开检查失败也不排除。
- B 是既有规则管理组，两个候选并行，各实际调用一次，按声明顺序选 candidate-1；不是模型 Manager 的自主分工。
- 两组独立环境，不共享产物、会话或评分。最终评分在提交冻结、Worker 关闭后进行。
- 正常完成时 token 来自 Codex turn.completed usage，超时时来自会话最后一条 token_count 累计记录（在途请求可能未计入）；输入含重复上下文和缓存，不能直接换算订阅费用。reasoning_output_tokens 属于输出子集，不再重复相加。B 汇总两个 Worker。
- 执行墙钟时间包括外部公开检查，B 还包含入选复查；不是两个 Worker 时长之和。B 首次评分网络失败并恢复，所以其端到端时间不能直接解释为管理开销。成功评分阶段单列。
- B 是历史开发试跑，A 使用修正后的评分网络配置和冻结脚本；A 额外显式禁用 hosted image/browser/computer 功能并收紧模型代理工具类型，主要任务条件一致，但非严格同时冻结的随机对照。
- 每组仅一次、单题，不能证明总体成功率或稳定收益；未按隐藏反馈修改实现或重跑取最好结果。
